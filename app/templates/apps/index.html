1. A folder with your app and a manifest.json


my-sensor/
  manifest.json
  requirements.txt        Python packages, installed in the version's own venv
  app/main.py
  wheels/                 optional: wheel files, for nodes without internet


{
  "name": "my-sensor",
  "version": "1.0.0",
  "description": "Reads the sensor and publishes it",
  "run": "python app/main.py",
  "requirements": "requirements.txt",
  "env": {"INTERVAL_S": "10"},
  "health": {"within_s": 20, "http": "http://127.0.0.1:8080/health"},
  "stable_after_s": 600,
  "groups": ["dialout"],
  "ports": [8080],
  "memory_max": "256M",
  "cpu_quota": "50%"
}

            
2. Pack it (any computer with Python 3)


python3 esapp.py pack my-sensor        # makes my-sensor-1.0.0.esapp, checked like a node checks it

            
3. Upload it here, roll it out

            
Packages: upload, then Roll out to the nodes you pick. Each node receives it in ~/Downloads/edgeshell and esapp installs it:


/opt/edgeshell/apps/my-sensor/
  versions/1.0.0/        your files, venv/, manifest.json, es-my-sensor.service,
                         install.sh, rollback.sh, uninstall.sh   (read-only)
  current -> versions/1.0.0
  data/                  APP_DATA: your files, kept across versions
  ota/                   every package received
/etc/systemd/system/es-my-sensor.service   user es-my-sensor, starts at boot, restarts on failure,
                                           logs in the journal (journalctl -u es-my-sensor)

            
Rules every app follows

            
    
                
  • Write only to $APP_DATA. The code, the venv and the rest of the system are read-only for the app.
    • 
                
  • Python packages only through requirements: they go into the version's own venv, never system-wide.
    • 
                
  • A version never changes: fix something, raise the version. A version that failed on a node is never installed there again.
    • 
                
  • Health: the service must stay up for health.within_s seconds (and answer its health check) or the node goes back to the previous version by itself. After stable_after_s without a restart the version counts as stable.
    • 
                
  • The newest {{ min_stable }} stable versions always stay on the node for a one-click rollback. Clean up removes only older ones.
    • 
                
  • Remove takes away everything: service, versions, OTA copies, user and data (or keeps the data in /opt/edgeshell/kept if you ask).
    • 
            

            
Full guide: docs/APPS.md in the EdgeShell repository. esapp {{ esapp_version }}.
